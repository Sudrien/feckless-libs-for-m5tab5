# The feckless ABI's crypto section, version 1 (8003).
#
# What an app's ELF may take from a launcher that links the section's
# component, feckless_abi_crypto -- one symbol a line, as exports.txt.
# The launcher defines the "@symbol"; an app that takes any name below
# refers to it (feckless_abi_require_crypto()), so a launcher without the
# section refuses the app by that name instead of failing on its first
# certificate. Lines that are not a bare name are ignored.
#
# Mbed TLS is in the launcher already (the HTTPS server, the HTTP client),
# and IDF 5.5 ships 3.6 where IDF 6.1 ships 4.0, which moved the public
# surface: no ecp.h or sha256.h, keys and hashes through PSA. The names an
# app takes depend on which it was built against, so a "@when mbedtls N"
# line starts the names that exist for that major only, until the next
# "@when" or an "@end"; the launcher's table lists its own major's, and
# the build check accepts either. Every structure below (mbedtls_pk_context,
# mbedtls_x509write_cert, psa_key_attributes_t) is laid out by the Mbed TLS
# that compiled it, so the app's major must be the launcher's: each
# major has a marker symbol that only a launcher of that major defines, and
# feckless_abi_require_crypto() refers to the app's. An app built for the
# other one fails in esp_elf_relocate() naming it.
#
# The launcher's Mbed TLS must be built with what the names below need:
# on IDF 6, CONFIG_MBEDTLS_X509_CREATE_C (the X.509 writer, which IDF 5
# always built); the component fails the build without it. Where the
# structures depend on other options, the same rule as the network
# section's: the app is compiled with the launcher's configuration.
#
# What is not here: the TLS stack, which an app reaches through the
# network section's HTTP client and server, and the PSA functions
# nothing in this repository's apps calls. The static inline functions in
# Mbed TLS's headers (mbedtls_pk_ec(), psa_set_key_type() and the other
# psa_set_key_*) have no symbol; mbedtls_pk_ec() calls
# mbedtls_pk_get_type(), which is here.
#
# Adding a name is compatible. Removing one, or changing what one means,
# is a new section version: crypto_v2.
@symbol feckless_abi_crypto_v1

# ---- Mbed TLS 3.6 (IDF 5.x) -------------------------------------------
# A P-256 key through the pk layer, a SHA-256 in one call, and PBKDF2 by
# the old function.
@when mbedtls 3

@end
